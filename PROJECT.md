# Simple Chat — техническое задание для DevOps

> Легенда: команда разработки закончила фичу (простой чат-мессенджер) и передаёт
> её тебе как DevOps-инженеру. Ниже — всё, что обычно даёт dev-команда:
> архитектура, сервисы, порты, переменные окружения и от чего что зависит.
> Твоя задача — самостоятельно написать `Dockerfile`-ы и `docker-compose.yml`,
> которые всё это поднимут.

## 1. Что за проект

Простой чат: пользователь вводит имя, попадает в общую комнату `#general`,
видит историю последних сообщений и общается в реальном времени с другими
подключёнными пользователями.

- Backend: Node.js, Express (REST) + Socket.IO (WebSocket).
- Frontend: статичные HTML/CSS/JS, без сборки — просто раздать файлами.
- Хранилище истории сообщений: PostgreSQL.
- Redis: используется как adapter для Socket.IO — нужен, чтобы чат работал
  корректно, если backend когда-нибудь будет запущен в нескольких репликах
  (pub/sub между инстансами).

## 2. Архитектура

```
                     ┌────────────┐
   браузер  ───────▶ │  frontend  │  статика (html/css/js)
      │              └────────────┘
      │ REST + WebSocket (напрямую из браузера)
      ▼
┌────────────┐     ┌────────────┐     ┌────────────┐
│  backend   │────▶│  postgres  │     │   redis    │
│ (node.js)  │     │  (данные)  │     │ (pub/sub)  │
└────────────┘     └────────────┘     └────────────┘
      ▲                                     ▲
      └─────────────────────────────────────┘
             socket.io redis-adapter
```

**Важный нюанс сети**: frontend — это статические файлы, которые исполняются
в браузере пользователя, а не внутри docker-сети. Значит браузер должен уметь
достучаться до backend напрямую — порт backend нужно пробросить на хост
(`ports:`), недостаточно просто общего `network` в compose.

## 3. Сервисы и требования к контейнерам

| Сервис    | Образ / билд                  | Порт (внутр.) | Порт наружу (рекоменд.) | Persist? |
|-----------|--------------------------------|---------------|---------------------------|----------|
| frontend  | билдится из `./frontend`       | 80 (если nginx) | 8080                     | нет |
| backend   | билдится из `./backend`        | 4000          | 4000                       | нет (данные в postgres) |
| postgres  | официальный образ `postgres`   | 5432          | не обязательно наружу      | да, volume |
| redis     | официальный образ `redis`      | 6379          | не обязательно наружу      | нет (это pub/sub, персистентность не нужна) |

### backend

- Стартовая команда: `npm install && npm start` (или собери образ с `node:20-alpine`).
- Слушает порт из `PORT` (по умолчанию 4000).
- При старте сам создаёт нужную таблицу в Postgres (миграций нет, схема
  создаётся кодом) — но это значит, что backend **должен запускаться позже**,
  чем становится доступен postgres, иначе будет падать. В коде уже есть
  retry-цикл на 15 попыток с паузой 2 сек, но правильная практика — добавить
  ещё и `depends_on` с `condition: service_healthy` + healthcheck на postgres.
- Переменные окружения (см. `backend/.env.example`):
  - `PORT`
  - `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
  - `REDIS_HOST`, `REDIS_PORT`
- Health-эндпоинт: `GET /health` → `{ "status": "ok" }` — можно использовать
  для healthcheck контейнера или для проверки готовности из compose/CI.

### frontend

- Чистая статика: `index.html`, `style.css`, `app.js`. Никакой сборки не
  требуется.
- По умолчанию ходит на `http://localhost:4000`. Если хочешь другой адрес
  backend (например, имя сервиса в сети), пробрось его через маленький
  `config.js`, который отдаётся до `app.js` и задаёт `window.CHAT_API_URL`.
- Как раздавать — на твой выбор: `nginx:alpine` с volume/`COPY` статики,
  либо любой лёгкий http-сервер.

### postgres

- Официальный образ, например `postgres:16-alpine`.
- Обязательно используй **volume** для `/var/lib/postgresql/data` — иначе
  вся история�──а пропадёт при `docker compose down`.
- Нужные переменные: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
  (должны совпадать с `DB_USER` / `DB_PASSWORD` / `DB_NAME` у backend).

### redis

- Официальный образ, например `redis:7-alpine`. Конфигурация по умолчанию
  подходит, ничего специально настраивать не нужно.

## 4. Локальный запуск без Docker (чтобы проверить, что код рабочий)

```bash
# backend
cd backend
cp .env.example .env   # поправь хосты на localhost, если нужно
npm install
npm start               # поднимется на http://localhost:4000

# frontend (в отдельном терминале)
cd frontend
npx serve .              # либо просто открой index.html в браузере
```

Для локального запуска тебе также понадобятся локальные Postgres и Redis
(или временно закомментируй проверку и просто убедись, что backend
запускается) — либо сразу переходи к Docker Compose, ради которого всё
это затевалось.

## 5. Твоя практика (DevOps-─━ть)

Файлы `Dockerfile` и `docker-compose.yml` в проекте **намеренно отсутствуют** —
это и есть задание. Чеклист, что стоит сделать:

1. [ ] `backend/Dockerfile` — образ на базе `node:20-alpine`.
2. [ ] Способ раздать `frontend` (свой `Dockerfile` с nginx, либо просто volume).
3. [ ] `docker-compose.yml` с 4 сервисами: `frontend`, `backend`, `postgres`, `redis`.
4. [ ] `.env` / `environment:` — прокинуть все переменные из таблицы выше.
5. [ ] `depends_on` с healthcheck для postgres и redis (не просто порядок
       запуска — реальная проверка готовности).
6. [ ] Именованный volume для postgres, чтобы данные переживали `down`/`up`.
7. [ ] Отдельная docker-сеть (можно default, но полезно завести своё имя).
8. [ ] Проверить: после `docker compose up`, история��ообщений �охраняется
       после `docker compose down && docker compose up` (без `-v`).
9. [ ] Проверить: `docker compose down -v` действительно чистит данные.

### Задания��о звёздочкой (когда основное заработает)

- Добавить `nginx` как reverse proxy перед frontend + backend (единый вход,
  один порт наружу вместо двух).
- Поднять `backend` с `--scale backend=2` и убедиться, что сообщения всё
  равно долетают всем через redis-adapter.
- Добавить `adminer` или `pgadmin` сервисом, чтобы смотреть содержимое
  Postgres через браузер.
- Добавить `restart: unless-stopped` и здоровый `healthcheck:` каждому сервису.
